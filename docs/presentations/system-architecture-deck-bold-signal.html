Infrastructure as Code

The Terraform foundation

  • Reusable modules live in infra/modules/, composed per environment under infra/envs/{dev,staging,prod}/.
  • Region ap-southeast-1, provider hashicorp/aws ~> 5.0.
  • Remote state in per-environment S3 backends with DynamoDB locking via backend.tf.
  • Secrets — Aurora master password is generated and stored in Secrets Manager, never hardcoded.

04 04 / 08
Composition

Seven modules

vpc

Subnets across N AZs, IGW, NAT (shared or 1/AZ), route tables, optional flow logs.

security-groups

Layered ALB→ECS→RDS chain via source-SG refs. No CIDR on the DB port.

aurora

PostgreSQL cluster + instances, subnet group, Secrets-managed creds, encryption, monitoring.

alb

App LB, IP target group for Fargate, HTTP/HTTPS listeners (TLS 1.3), optional access logs.

ecs

Fargate cluster, task def, service w/ circuit breaker, immutable ECR + scan, IAM roles, logs.

s3 · lambda

S3: versioned, SSE, public-access block, TLS-only. Lambda: VPC-attached, single-source guard.

Security Posture

Defense in depth

  • ECS tasks have no public IP — only the ALB is internet-facing.
  • DB reachable only from ECS/Lambda SGs — never 0.0.0.0/0 on 5432.
  • Aurora storage encrypted; password is random + Secrets Manager.
  • S3: all four public-access blocks, BucketOwnerEnforced, TLS-only policy.
  • Prod ALB fails plan without an ACM certificate — no cleartext prod traffic.
  • CloudWatch log groups support optional CMK encryption (log_kms_key_id).
